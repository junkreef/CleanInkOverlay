# 署名 (画像で文字列を見分ける)

ステージ名・モード・ルール・表彰名などは、OCR で読まずに**白文字 (表彰は暗い字) のマスクを固定サイズのベクトルにした「署名」**で同じかどうかだけを判定する。同じ文字列なら相関が高く、違う文字列は低い。名前は、初めて見た署名に id を付けて保存しておき、人があとから一度だけ付ける。

- ライブラリ: `assets/signatures.json` (`id → {kind, label, sig}`)。`work/signatures.py` の `Library`。
- id は kind の頭文字 + 署名の md5 の 8 桁 (`s_…` ステージ、`m_…` モードと表彰、`r_…` ルール、`t_…` ルール画面のルール名、`p_…` パネルのブキ)。
- `identify(sig, kind, thr)`: 同じ kind で同じ長さの署名と相関を取り、一番高いものが `thr` 以上ならその id とラベル。無ければ新しい id で追加する (`add_unknown`)。長さの違う署名は古い切り出し方で作ったもので、同じ文字列ではない。
- 保存 (`Library.save`) はファイルの内容と合わせてから書く。別のプロセス (レコーダーの動いている間に Web UI でラベルを付けた、など) が付けたラベルを、古いメモリの内容で上書きしないため。

## 種類

| kind | 何の文字列 | 切り出し | しきい値 |
|---|---|---|---|
| `stage` | ステージ名 (リザルト表・個人パネルのバナー) | 固定の位置から固定幅のキャンバスに置く (`result_parser.banner_signature`) | 0.85 (`BANNER_THR`) |
| `mode` | モード (レギュラーマッチ、バンカラマッチ(チャレンジ)、イベントマッチ、フェスマッチ(オープン) など) | 同上 | 0.85 |
| `rule` | ルール名 (バナー) | 同上 | 0.85 |
| `title` | ルール画面の中央の大きなルール名 | 固定のキャンバス (`rule_screen.title_signature`) | 0.8 (`recorder.TITLE_THR`) |
| `medal` | 表彰名 (「○○ No.1」) | 本文の外接矩形 192x32 + 最後の字 24x24 (`medals.banner_signature`) | 0.8 (`medals.MEDAL_THR`) |
| `panel_weapon` | 個人パネルのブキカードのアイコン | 24x24 カラー縮小 (`panel.weapon_signature`) | 0.97 (`panel.WEAPON_THR`) |

キルフィードとリザルト表の名前も同じ考えの署名 (`signatures.signature`: 白文字の外接矩形を 96x16 に縮小) で比べるが、これはライブラリに入れず、同じ試合の中で突き合わせるだけ ([hud.md](hud.md#自分のキル-キルフィード))。7 画面 56 行で、同じ名前同士の相関は 0.81 以上、違う名前同士は 0.39 以下。

**プレイヤー名は記録しない** (ランダムマッチなので相手の同一人物判定はしない)。以前あった kind `name` は、ライブラリの読み込み・保存のときに捨てる (`DROPPED_KINDS`)。ルール画面のカードの名前 (45 px の太字) とリザルト表の名前 (20 px の細い字) は同じフォントでも署名の相関が正解 0.08〜0.63 と弱く、誤答と逆転もしたので、名前でカードと行を結ぶことはしない (ブキアイコンで結ぶ)。

## バナー

リザルト表と個人パネルの右上の黒いタグの白文字。

- 白 = 全チャンネル > 190 で彩度の低い画素 (まわりのステージの写真は鮮やか)。文字の左上は全画面で同じ位置 (ライブも録画も) なので、外接矩形で切らずに**固定幅のキャンバス**に置く。外接矩形だと、ステージの写真の明るい点 1 つで全体がずれた。12 px 未満の点は消す。
- 位置 (`result_parser.BANNER`): モード x 841・y 48・高さ 18・幅 140、ルール x 837・y 89・高さ 31・幅 200、ステージ x 1061・y 96・高さ 23・幅 280。上の余白の行が黒でなくなる所でタグの終わりとし、キャンバスをそこで切る。署名はキャンバスを半分に縮めたもの。
- 幅 40 px (`BANNER_MIN_W`) より狭い白は文字ではない (一番短いバイガイ亭で 86 px。8 px の点が誰も見ていない「ステージ」になったことがある)。
- 同じ文字列は別の画面でも 0.99 以上、一番近い別のステージ名どうしで 0.61。
- **ステージ名の開始位置**: ステージ名はルール名と同じタグの中でルール名に続くので、ルール名の幅で動く。
  - 7 文字のルール名 (ナワバリバトル、ガチホコバトル) のあとは x 1061、5 文字 (ガチヤグラ) のあとは 56 px 左の x 1005。`result_parser.stage_x` がルール名とステージ名の間の文字の無い隙間を x 1061 と x 1005 の手前で探して決める (`STAGE_SHORT_RULE = 56`)。
  - ガチアサリは同じ 5 文字でも字が広く、x 1011 から。署名は 1 px ずれると 1.0 → 0.88、2 px で 0.64 まで下がる。なので `banner_identify` は stage_x の −2〜+8 px (`STAGE_SHIFT`) で照合し、一番よく合う位置を採る。どこにも合わなければ stage_x の位置で新しい署名にする。ガチエリアのリザルト画面はまだ 1 枚も保存されていないので、そのあとの位置は未確認 (ガチヤグラのあとは +0、ガチアサリのあとは +6 で合った)。幅に入らなかったときは同じステージ名がもう 1 つの署名として残るだけなので、Web UI で名前を付ければ済む。
- イベントマッチのバナーは上段のタグが 2 つ (「イベントマッチ」「ツキイチ・イベントマッチ」)。1 つ目はモードの位置で読める。2 つ目は読んでいない。

## ルール画面のルール名

ルール画面の真ん中、黒いインクの上の白い大きな文字 (2 行、y 387〜610、x 740〜1180 の範囲、`rule_screen.TITLE`)。白で彩度が低く、近くに暗い画素がある画素 (背後の明るいステージは数えない) の、30 px 未満の点を消したマスクを固定のキャンバスに置き、1/4 に縮める。白が 400 px 未満なら名前なし。

- 保存済みのナワバリのルール画面 269 枚は全部同じ署名 (相関 0.91 以上)。ガチホコバトルとは 0.63、ヤグラ・エリアとは 0.2 前後 → しきい値 0.8。
- レコーダーはこの名前で解析を切り替える ([ranked_rules.md](ranked_rules.md#解析の選び方))。ラベルの無いルール名ではタイマーで決める。
- 名前の付いているもの (2026-11-04 時点): ナワバリバトル、ガチホコバトル、ガチヤグラ、ガチエリア、ガチアサリ。

## 表彰

表彰名はほとんどが「○○ No.1」(または No.2) で終わるので、別の文字列でも似やすい (旧方式の 96x16 の署名では別の名前どうしで 0.6〜0.76 あった)。

- 本文の暗い字のマスクを、3 枚のレイアウトの大きさ (315x65) にそろえてから外接矩形を 192x32 に縮め (1 文字の違いで決まることがあるので名前より細かい)、最後の字 (「1」/「2」) を 24x24 で足す。「塗りポイント No.1」と「No.2」は最後の字しか違わない。
- 保存済みの画面で、同じ名前は 0.89 以上、一番近い別の名前で 0.72 → しきい値 0.8。
- 斜めのバナーの外の黒い背景が端に写るので、端に接する幅の広い成分と、高すぎる成分 (40 px 超) と、15 px 未満の点を消す。
- 名前の付いた例: バトル No.1、塗りポイント No.1、ホーム塗り No.1、アウェイ塗り No.1、注目された時間 No.1、トドメ数 No.1、移動距離 No.1、アシスト数 No.1、サメライド No.1、ファーストスプラット など。
- 金 / 銀は左のイカのアイコンの色で決める ([result_screens.md](result_screens.md#表彰-workmedalspy))。

## ラベル付け

- Web UI の「未知のステージ・表彰」タブ (`GET /api/signatures/unlabelled`、`POST /api/signatures/label {id, label}`)。種類で絞り込め (ステージ / 表彰 / モード / ルール / ルール (開始画面))、その署名が写っている保存画面を見て名前を入れる。
- 名前を付けると (`Store.label_signature`)、その id で保存されていた試合も埋まる: 表彰は `medals.name`、ステージ / モード / ルールは raw_json の `stage_id` / `mode_id` / `rule_id` が一致して列が空の試合、ルール画面の名前 (`title_id`) は `matches.rule`。
- 保存画面がもう無い未ラベルの署名は `POST /api/signatures/prune` (`Store.prune_signatures`) で消せる。次にその文字列が出たとき、画像付きでまた登録される。
- コードから付けるなら `signatures.Library().label(id, 名前)` → `save()`。ただしバックエンドの動いている間は Web UI から付ける (Store がライブラリを持っているため)。

## 作り直し

文字の切り出し方を変えたら、`work/rebuild_signatures.py` で保存済みの画面から作り直す。保存済みのリザルト画面 (ステージ / モード / ルール) と表彰画面をいまのコードで読み直し、DB が知っている名前でラベルを付け、DB の参照 (`medals.sig_id`、raw_json の `*_id`) を新しい id に移す。`panel_weapon` は残す。

```
python work/rebuild_signatures.py            # 試し実行 (変わるものを表示)
python work/rebuild_signatures.py --apply    # ライブラリと DB に書く (先に両方のバックアップを取る)
```
