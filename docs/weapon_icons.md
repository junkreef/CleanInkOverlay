# ブキアイコンの判定

`work/weapon_match.py` (照合)、`work/weapon_icons.py` (テンプレートとサンプル)、`work/recorder.py` (`harvest_icons`、HUD との紐づけ)、`work/hud.py` (`masked_ncc`)。

ブキはリザルト表の各行のアイコン (56 px、背景はほぼ黒のパネル) で決める。HUD のイカ枠のアイコンではブキを決めない (イカ / タコの塗り色が試合ごとに変わり照合が安定しない)。HUD のスロットには、リザルト表で決めたブキを紐づける ([下](#hud-スロットとリザルト行の紐づけ))。

## 照合の基本

キャプチャ側の背景を抜くのではなく、**見本のアイコン (RGBA) をキャプチャと同じパネルの色に合成してから、色付きのままテンプレートマッチ** (TM_CCOEFF_NORMED) する。パネルの色は切り出しの暗い画素 (グレー < 70) の中央値。

- 正解は 0.94〜0.97 で、配色違い (カーボンローラーANGL / デコ、オーダーのレプリカなど) も 0.05 以上の差で分かれる。
- 形だけ・グレースケールの照合では配色違いを区別できない。色付きでも背景を合わせないと全滅する。
- 一番よい一致度が 0.85 未満 (`UNKNOWN_BELOW`) なら「不明」とし、候補 3 つを付ける。

`result_parser.parse` が各行に付ける値:

| キー | 意味 |
|---|---|
| `weapon` | ブキ名。不明 (0.85 未満) か `variant` なら None |
| `weapon_score` | パネルの色での相関 (系統の確からしさ、正解は 0.9 台) |
| `weapon_conf` | 1 段目ではっきり決まれば 1.0、配色違い・スコープ違いの判定をしたときはその信頼度 |
| `weapon_stage` | `natural` (1 段目) / `pair` (2 候補の判定) / `variant` (テンプレートに無い部品がある) |
| `weapon_alt`, `weapon_candidates` | 2 位、上位 3 つ |
| `weapon_unknown` | 未知アイコンのグループ id (レコーダーが付ける) |

DB の `match_players.weapon_score` / `weapon_conf` はこの値。

## アイコンのセット

配布するのは**自分たちのリザルト表から切り出したテンプレート**だけ (`assets/weapon_icons_captured/<ブキ名>.png`、RGBA 56x56。2026-11-10 時点でメイン 174 種の全部 + ブキ無し)。

- 環境変数 `CLEANINK_WEAPON_ICONS=captured|wiki|both` (既定 `both`) で使うセットを選ぶ。`both` はテンプレートを優先し、テンプレートの無いブキだけ wiki アイコンを使う。`captured` で動かすと、wiki アイコンの無い配布版と同じ動きになる。

### wiki アイコンの扱い

`assets/weapon_icons/` (wiki のアイコン。読み込みには分類ファイル `assets/weapon_icons_sections.json` も使う) は**ライセンスが無いので配布しない**。手元にあるときだけ、次の用途で使う任意の参照:

- 開発用ツール `work/harvest_icons.py` (保存済みのリザルト画面からテンプレートを最初に作る) と `work/eval_icons.py` (テンプレートと wiki アイコンの答えの比較)。
- レコーダーでは、新しいテンプレートの最初のサンプルの位置合わせと、ブキ以外の画素の切り落とし、テンプレートの無いブキの推定 (下の「確認待ち」)。

無ければ `load_wiki_icons` は空を返し、テンプレートだけで動く。

## テンプレートの作り方

- 1 つのブキのサンプル (リザルト行の切り出し 70x90、`data/icon_samples/<ブキ>/<stamp>_<行>.png`) を位置合わせし、**画素ごとの中央値**を取る。アルファ = パネルの色と違う画素 (ライブではパネルはちょうど (2, 2, 2) なので許容 1、`BG_TOL`)。中央値なので、ラベル違いや傷のあるサンプルが 1 つ混じっても、数が集まれば消える。
- 行の上下の区切りの帯 (幅 76 px のほとんどが前景の行) はアルファから外す。
- アイコン右下のバッジ (「89」やブランドのロゴなど) はブキの種類の一部なので残る。
- サンプルは 1 ブキ最大 8 (`MAX_SAMPLES`)、同じ行の位置から最大 2 (`MAX_PER_ROW`)。8 つの行はそれぞれアイコンを 1 画素未満ずれて描くので、1 つの行だけのテンプレートはその行にしか合わない (lose4 の行だけで作ったリッター4K は win3 の行を 4Kスコープと読んだ)。
- 配布されたテンプレート (手元にサンプルが無い) は、手元のサンプルが 8 つそろうまで作り直さない (`MIN_TO_REPLACE`)。配布版 (zip) では、作り直したテンプレートはデータフォルダに書き、配布されたファイルは変えない ([release.md](release.md#配布したライブラリと使う人が足した分))。3 つで作り直したら パラシェルター / スプラローラー / .96ガロン爪 のテンプレートがほかの行に合わなくなった。
- HUD 用には、リザルト表の黒い影と暗い縁 (最大チャンネル < 24) をマスクから外し、縁を 1 px 削ったもの (`without_shadow`) を使う。

### サンプル集め

試合を保存するとき、**ライブのリザルト表だけ**から集める (`Recorder.harvest_icons`)。録画 (H.264) はパネルの色がにじみ、アルファがノイズになる。

- 一致度 0.94 以上 (`HARVEST_MIN_SCORE`)、配色違い・スコープ違いの判定をしたなら信頼度 0.1 以上 (`HARVEST_MIN_PAIR_CONF`) の行を、そのブキのサンプルにする。
- 切り出しのパネルが平らか (パネルの色ちょうどの画素が 30% 超、`lossless`) を確かめる。
- テンプレートが変わったら (`IconLibrary.version`)、レコーダーはアイコンのセットを読み直す。

## 2 段目: 近い 2 つの判定

1 段目 (パネルの色での相関) で 2 位との差が 0.05 以内、または 0.15 以内 (`SHAPE_CLOSE`) で 2 つが「形の兄弟」なら、上位 2 つを 2 段目で決める (`pair_decision`)。

### スコープ違い (形で決める)

リッター4K / 4Kスコープ のような、スコープの筒の有無だけが違うペア。ゲームはスコープの筒をパネルよりわずかに明るいだけの暗い色で描く (純黒 0 のパネル 2 の上、など) ので、色の比較ではほとんど差が出ない (スコープ付きの行でもリッター4K が 0.05〜0.08 上に来た)。

- **パネルは 1 色の塗りつぶしなので、パネルの色でない画素 = アイコンの形** (`shape_decision`)。パネルの色から 4 (`SHAPE_TOL`) 以上離れた画素を形とし、2 つのテンプレートのどちらか一方にしかない部分 (3x3 で開いて 1〜2 px の縁を消す) の中に、切り出しの形がどれだけあるかで決める。信頼度 = 両者の割合の差。許容 4 は H.264 の録画でも成り立つ (8 にすると暗いスコープが消え始める)。
- **形の兄弟** (`shape_siblings`): 2 つのテンプレートが互いに 0.9 以上 (`SIBLING_CROSS`) で合い、一方にしかない部分がスコープくらいの大きさ (60 px 以下、`SIBLING_PART`。スコープのペアは 40〜53 px、ほかで同じくらい似ている カーボンローラーANGL / デコ は 113 px)。ゆるくするとレプリカや無関係なブキが形の判定に回って当て推量になった (パラシェルター を オーダーシェルター レプリカ と読んだ)。この条件に当たるのはちょうど 5 つのスコープのペア:

  | スコープなし | スコープあり |
  |---|---|
  | リッター4K | 4Kスコープ |
  | リッター4Kカスタム | 4Kスコープカスタム |
  | スプラチャージャー | スプラスコープ |
  | スプラチャージャーコラボ | スプラスコープコラボ |
  | スプラチャージャーFRST | スプラスコープFRST |

- 保存済みのスコープのペアの 89 行は、形の答えを人が全部確かめた (2026-10-15)。それまでの照合 (wiki アイコン) は 52 行中 34 行でリッター4K / 4Kスコープを逆にしていた。

### 配色違い (差分の領域で決める)

形が同じ 2 つは、2 つのアルファマスクが違う領域 (3 px 膨張) だけを見る。切り出しのパネル色の画素 (許容 2) を白に置き換え、白に合成した各候補との平均絶対残差を比べる (位置合わせは ±1 px で残差合計が最小のところ)。信頼度 = (負けた側の残差 − 勝った側) / 和 で、正解付きのサンプルで 0.13〜0.24。

全体の相関で比べないのは、白に置き換えた全体の相関が正解でも 0.5〜0.65 と低く (アイコンの輪郭のアンチエイリアスが白に対して暗い縁になる)、1 位と 2 位の差も 0.01〜0.12 で不安定だったため。

## テンプレートに無いブキ (`variant`)

1 段目で勝ったのが自前のテンプレートで、切り出しにテンプレートに無い部品があれば (`extra_parts`)、ほぼ確実にテンプレートのまだ無い別のブキ (オーダーのレプリカ、デコ、コラボ、スコープ付き) なので `weapon_stage = 'variant'` にして不明扱いにする。

- 部品 = 形がテンプレートと食い違う (パネルの色との差が 4 を超えるかどうかが、テンプレートのその画素と上下左右 4 近傍のどれとも合わない) か、色がテンプレートの範囲から 12 (`VARIANT_COLOUR`) 以上外れる画素を 3x3 で開いたもの。15 px 以上 (`VARIANT_PART`) で `variant`。近傍で許すのは、行によってアイコンが 1 px ずれるため (3x3 の箱ではゆるすぎてレプリカの塗り替えた縞を通した)。
- 正解のテンプレートを抜いて試すと、4K のペア以外の兄弟の取り違え 203 件中 174 件を捕まえ、正しい一致 1311 件では 1 件も誤って当たらなかった (2026-10-15)。4K のスコープは暗すぎて形の許容 4 に引っかからないが、4K は両方のテンプレートがある。

## 未知のアイコン

どのテンプレートにも合わないアイコンは「未知のグループ」として貯め、人が Web UI で一度名前を付ける。

- グループは見た目ごとに 1 つ (`data/icon_samples/_unknown/<id>/`、id は `u` + 8 桁)。新しいアイコンは、グループのテンプレートと 0.85 以上で合い、どちらにも無い部品が無ければそのグループに入る (`fit_group`)。どれにも入らなければ新しいグループ。行に `weapon_unknown = <id>` が付く。
- **確認待ち**: wiki アイコンが名前を付けたが一致度が低い (0.85 以上 0.94 未満、例: ホットブラスター艶 0.926、ソイチューバー 0.93) アイコンも、wiki の名前を「推定」(`guess.txt`) としてグループに入れる。そうしないと、そのブキはいつまでもテンプレートができない。
- グループは照合のアイコンのセットに入れない。1 つの悪い切り出しから作ったグループが既知のブキと競い、そのブキの後の行を取ってしまうため。照合のあとに `fit_group` で試す。グループのテンプレートは読み込みのたびにサンプルから作り直し、配布しない。
- 名前付け: Web UI の「未知のステージ・表彰」タブの「未知・確認待ちのブキ」(`GET /api/weapon_icons/unknown`、`POST /api/weapon_icons/label {id, name}`)。推定があれば入力欄に入っている。名前を付けると (`Store.label_weapon_icon`)、サンプルがそのブキに移り (足りない分だけ、残りは捨てる)、そのグループを見た試合の `match_players.weapon` と raw_json が埋まる (DB の移行は要らない)。
- ライブだけで作る (録画の H.264 の切り出しは `lossless` を通ることがあっても、既知のブキのグループを作るほどノイズがある)。

## HUD スロットとリザルト行の紐づけ

HUD の各スロットにはブキのアイコンが、フルカラー・回転なし・約 92 px (スロットの枠 70 px より大きい) で、チームの色のイカの上に描かれている。

- 試合開始のタイマー表示中 (ナワバリ 3:00、ガチ 5:00。全員生存) に、各スロットの周り (枠 + 28 px) を最大 3 回切り出しておく。デス中はアイコンが消えるため。
- テンプレートの不透明画素だけで正規化相関を取る (`masked_ncc`、`cv2.matchTemplate` のマスク付き TM_CCOEFF_NORMED、位置探索あり)。大きさは 88 / 92 / 96 px の最大。候補は**同じチームのリザルト表の 4 つのブキ**に絞る。
- チームごとに 4! 通りの割り当てのうち、「一致度の合計 − 0.05 × |HUD のデス回数 − リザルト表のデス数|」が最大のものを採る (`recorder.assign`)。同じブキが 2 人いるときはデス回数がタイブレークになる。
- `match_players.link_score` = 割り当てたブキとの一致度。開始のアイコンを見ていない試合は NULL (並びは任意)。
- 録画 2 本 5 試合で 40/40。HUD 用のテンプレートは影を外したもの (`without_shadow`) にする: 2026-10-11 の録画で、正しい割り当てと次点のチーム単位の差が 0.08 / 0.69 (そのまま) → 0.63 / 0.93 になった (wiki アイコンでは 0.88 / 1.11)。
- ガチアサリでは各ブキのアイコンの下に持っているアサリの数 (黄色いコイン) が重なるが、アイコンは試合開始のコマで取るのでまだ誰も持っていない。2 試合 16 枠すべて正しく結び付いた。デスの判定 (暗い灰色の割合) にもコインは効かない (彩度が高い)。

同じチームに同じブキが 2 人以上いると、その 2 人のスロットと行はアイコンでは決まらない。HUD のデス回数の差で補い、それも同じなら順列の順 (実質ランダム)。ブキ別の統計には影響せず、入れ替わるのは HUD のデス時刻の帰属とその行の成績だけ。キルフィードと吹き出しの相手は名前の署名 / カードで直接行に結ぶので影響しない。

## 開発用ツール

```
uv run python work/harvest_icons.py [--dry] [GLOB]   # 保存済みのリザルト画面 (既定 samples/matches/*_result.png) からテンプレートを作る
uv run python work/eval_icons.py [GLOB]              # テンプレート (leave-one-out) と wiki アイコンの答えを比べる
python work/weapon_match.py [FRAME.png]               # 1 画面の 8 行を照合して表示
```

- どちらも wiki アイコンが手元にあることが前提。`harvest_icons.py` は H.264 の録画の画面を飛ばし、スコープのペアは最初に明るさ (wiki のスコープの形の中の平均の明るさ) でラベルを付けてから、テンプレートができたあと形 (`shape_decision`) で全部確かめ直して、食い違えば移す (明るさは行で変わる: lose1 の行のリッター4K が 14.7)。`assets/real_icons/` の手切りの切り出しも、wiki アイコンが欠けている / 悪いブキの代わりに使う。
- `eval_icons.py` はその画面から作ったサンプルを抜いてテンプレートを作り直して比べる (一度も見ていないブキの画面と同じ条件)。
