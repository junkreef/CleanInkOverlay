# ガチルール (ナワバリ以外のルール)

ガチホコ・ガチヤグラ・ガチエリア・ガチアサリ (バンカラマッチ) と、イベントマッチの名前の無いルールの扱い。画面の流れは [match_flow.md](match_flow.md#ガチルール-バンカラマッチ)。

確かめた録画: `2026-10-28_22-51-57.mp4` (ガチホコ 2 試合、2 試合目はリザルト表なし)、`2026-10-28_23-06-42.mp4` (ガチヤグラ 4 試合、4 試合目はリザルト表なし・延長あり)、`2026-10-10_18-20-07` / `18-25-31` (ガチエリア、メモリープレーヤーの再生)、`2026-10-29_22-02-57.mp4` (ガチアサリ 2 試合、どちらも延長あり)。

## 解析の選び方

ルール画面の真ん中のルール名 (署名 kind `title`、[signatures.md](signatures.md#ルール画面のルール名)) で決める (`recorder.RULE_ANALYSIS`)。

| ルール名 | 解析 | 試合中に読むもの |
|---|---|---|
| ナワバリバトル | `turf` | 3:00、塗りポイント、塗り % |
| ガチヤグラ、ガチホコバトル | `track` | 5:00、ヤグラ / ホコの線 |
| ガチエリア、ガチアサリ | `zones` | 5:00、両チームのカウントとペナルティ |
| それ以外の名前 (イベントの新しいルールなど) | `other` | 開始時のタイマーの長さ。線とカウントは読まない |

- 名前がまだ無い (Web UI で名前を付けていない) か、ルール画面を見ていないときは、**開始時のタイマー**で決める: 3:00 = ナワバリ、それより長い (3 コマ) = ナワバリ以外。名前の無いナワバリ以外のルールは、線とカウントを毎秒探し、HUD の秒の 3 割以上で見えたものだけを残す ([下](#ガチヤグラ--ガチホコ-線))。
- 名前がナワバリなのにタイマーが 5:00 なら、ログに出してタイマーに従う。
- 試合の長さは、ガチは 5:00、名前の無いルールは最初に読めた値を分単位に切り上げたもの。
- 新しいルールも安全に記録できるようにするため、名前の分からないルールでも、キル・デス・スペシャル・勝敗・成績は普通に取る。
- ルール画面を見ずに途中から通した試合は、リザルト表のバナーのルールにラベルが無いとナワバリ扱いになる。ガチのルール名 (バナーの `rule` とルール画面の `title`) には名前を付けておく。

## ナワバリ以外の試合で共通のこと

- **HUD の判定**: 右上の塗りポイントが無いので、タイマー欄 (`hud.timer_hud`: M:SS が読めるか「延長中!」) で見る ([hud.md](hud.md#hud-が見えているか))。試合中は、経過時間と 3 秒以上合わない読みのコマは HUD なし (マップやスーパージャンプがタイマー欄にかかって「7:99」「0:99」と読め、デスを多く数えていた: ヤグラ 1 試合目で +4 → +1)。
- **キル・デス・やられた吹き出し・スペシャル**: ナワバリと同じ読み取り。タイマーの位置、8 人の枠、キルフィード、吹き出し、復活までの文字はナワバリと同じ位置。
- **塗りポイントと % は無い**。my_pct / enemy_pct は入れない (ジャッジくん画面とリザルト表の % の所はカウントか「ノックアウト!」)。
- **延長戦**: 0:00 のあと、タイマー欄が「延長中!」になる (最長 5 分、[hud.md](hud.md#延長戦))。0:00 か延長中のあとは HUD が 15 秒見えなくなるまで試合を続ける (延長中にやられるとマップが 10 秒ほど出る)。
- **ノックアウト**: 時間切れより前に終わるので、試合中にジャッジくん画面が出たらそこで試合終わりにする。
- **リザルト表が出ないとき**: ジャッジくん画面 (勝敗・カウント) と個人パネル (自分の行・ステージ・モード・表彰) で保存する。開始のイカ枠のアイコンが無ければ自分のスロットは 0 番 (`link_score` NULL)。ジャッジくん画面も個人パネルもリザルト表も無ければ保存しない。
- 確認 (ルール名は未登録 = タイマーで判定): 8 人のデスとリザルト表の比較で、ヤグラ 1 試合目 (ノックアウト) 29 / 28、2 試合目 54 / 54 (全員一致)、3 試合目 55 / 54、ホコ 1 試合目 (ノックアウト) 38 / 39。リザルト表の無い試合は自分のデスが一致 (ホコ 2 試合目 6 / 6、ヤグラ 4 試合目 8 / 8)。

## カウントとチームのポイント

`work/counts.py`。DB の `matches` の列:

| 列 | 意味 |
|---|---|
| `my_count` / `enemy_count` | 「N カウント」。ノックアウトした側は 100 |
| `knockout` | 1 = どちらかがノックアウト、0 = 時間切れ (両方のカウントが読めたとき)、NULL = 不明 |
| `my_team_points` / `enemy_team_points` | チームの「Np」(ジャッジくん画面のカウントの下、リザルト表の WIN! / LOSE... の行の右端) |

- **ノックアウトするとスコアは 100 : 0 になる**。負けた側の 0 は読み違いではない (エリアでは HUD で相手が 50 / 48 まで進んでいた試合、ホコでは相手が線の −92 まで進んでいた試合でも 0)。HUD での最後のカウントは timeline で見られる。
- チームのポイントは、見た例ではどれも最終値 = カウント × 5 (ノックアウト = 500p)。ただしカウントアップの途中は別々に動く (31 カウントで 158p、0 カウントで 1p) ので別の列にした。
- **ジャッジくん画面**: 左 = 自分のチーム。カウントの数字 (68 px、y 861〜931) はジャッジの % と同じ字形で、`judge` グリフで 0.98〜1.00。続くカタカナは 16 px ほど下から始まり少し低いので、「数字の並び + 下から始まる高めの箱」をカウントとみなす (ナワバリの「45.7%」の「.」は低すぎて外れる)。ノックアウトは白マスクのテンプレート (`work/templates/ko_judge.png`)。ポイント (39 px、y 957〜996、後ろに低い p) は `judge_p` グリフ (HUD の `points` のままだと 5 が 0.57)。片側ずつカウント (+ ノックアウト) とポイントを毎コマ投票し、2 コマ以上一致したものを使う。
- **リザルト表**: 上の帯 (y 244〜272) に左 = 自分のチームのカウントかノックアウト (`ko_scoreboard.png`)、WIN! / LOSE... の行に「500 p」。どちらも `pct` グリフ (0 で 0.88〜0.93、5 で 0.81)。リザルト表の帯で読めたのは 0, 2, 3, 4, 5, 6, 9。1・7・8 はまだ出ていない。
- リザルト表で読めなかった値はジャッジくん画面の値で埋める。食い違えばログに `judge check: MISMATCH` が出てジャッジくん画面の画像が残る。
- ナワバリでもジャッジくん画面とリザルト表の行に「Np」があるが読まない (カウントが読めた側・帯にカウントがある試合だけポイントを読む)。保存済みのナワバリの画面で何も読まないことをテストで確かめている (`test_turf_screens_have_no_counts`)。
- 確認: ガチホコ 1 試合目 100 / 0 / KO / 500 / 0 (リザルト表とジャッジくん画面が一致)、2 試合目 (リザルト表なし) 68 / 40 / 時間切れ / 340 / 200。ガチヤグラ 4 試合: KO 500p / 0、43 / 40 (215p / 200p)、62 / 90 (310p / 450p、負け)、89 / 88 (445p / 440p)。

## ガチヤグラ / ガチホコ: 線

`work/objective.py`。HUD のイカ枠の下 (y 155) に、自分のゴール側 (左、x ~510、自分のチームの色の丸) から相手側 (右、x ~1405) までの点線。中央 x ~958。

- 点は約 14 px おきで、毎回同じ位置にある (左右 30 個ずつ、x = 950 − 14k / 968 + 14k)。**黒い点 = どちらかのチームが一度進めた範囲** (左端 = 相手の最大、右端 = 自分の最大)、その外は各チームの色。ヤグラはチェックポイントの四角も線上に出る。
- ヤグラ / ホコは直径 ~40 px の丸いアイコンで線の上を動く。誰も乗っていない = 白い縁にオリーブの中、乗っている (持っている) = そのチームの色。
- チームの色は試合ごとに違うので、毎回線の両端の丸の色合い (hue) で見分ける (点やアイコンは両端より濃い)。
- 読み取り (`read`、1 秒に 1 回): アイコンを HoughCircles (半径 16〜24) で探して位置を −100 (自分のゴール) 〜 0 (中央) 〜 +100 (相手のゴール) に直し、アイコンの縁の色で誰が乗っているか (`obj_holder` = my / enemy / NULL)。各チームの進み (`my_best` / `enemy_best`、0〜100) は中央から続く黒い点の連なりの端 (アイコンやチェックポイントで 4 個まで隠れてよい)。進めているチームのアイコンが連なりの端を隠すので、端のすぐ先にそのチームのアイコンがあればアイコンの中心を端とする。
- 進みは「直近 3 回の読みの中央値」の累積最大 (`recorder.best_series`)。1 回の読み違い (点の上に何か) は数えない。
- **線が見えているか** (`present`): 両端の丸が明るく鮮やかで色合いの違う 2 色、かつ点の大半が読める。終盤は点がほとんど黒になるので、点の色では判定しない。名前の無いルールは、線が HUD の秒の 3 割以上 (`OBJ_MIN_SHARE`) で見えたときだけ残す (ガチエリアの録画で線の誤検出が 6% あった)。
- 名前の付いたルールでは、位置が読めるまで同じ秒の次のコマで読み直し、1 秒の中で一番よく読めたコマを使う (位置のある秒が 161 → 216 秒などに増えた)。
- **位置はカウントではない**。線の上の距離はカウントに比例しない (ルール・ステージで違う): ヤグラ 2 試合目は最大位置 +41 / −36 で最終カウント 43 / 40、ホコ 2 試合目は +67.9 で 68。アイコンはカウントの動かない所にも出る (乗り手が降りたあと流れるヤグラ、持ち主がやられて最後の地面に戻る空中のホコ)。最終カウントはジャッジくん画面から取れるので、線は「位置」として記録する。
- マップ表示・スーパージャンプ・やられた後のマップの間は HUD が無いので空く。

## ガチエリア / ガチアサリ

`work/area.py`。2 つのルールの HUD は同じ形で、同じ読み取りを使う。

- タイマーの下に、左 = 自分、右 = 相手の「のこり N」の箱 (100 から減る、数字 y 150〜214)。数字はタイマーと同じ字形で、`timer` グリフで読める (0.75〜0.91)。
- 箱が**光っている** (チームの色で塗られ、白い数字) チームがカウントを進めている。そうでないと黒い箱にチームの色の数字で少し小さい。
  - ガチエリア: 全部のエリアを確保している (またはペナルティを消化している) チーム。真ん中にエリアごとの確保状況のアイコン (マップによって 1 つか 2 つ)。
  - ガチアサリ: ゴールのバリアを割って攻めている間 (箱の間の円グラフが攻めの残り時間)。真ん中のアイコンは 1 つ (ゴール)。
- **記録**: 1 秒ごとに両チームのカウント (100 − のこり。ジャッジくん画面の「N カウント」と同じ向き) を timeline の `my_count` / `enemy_count` に、箱が光っている側を `obj_holder` に。カウントは減らない (ペナルティはカウントを戻さない) ので、ヤグラの進みと同じく「直近 3 回の中央値」の累積最大。両方のカウントが読めるまで同じ秒の次のコマで読み直す (エリアの録画で 259 秒中 259 秒、282 秒中 281 秒)。
- **ペナルティ**: 箱の下の暗い丸枠に白い「+N」(y 218〜262、味方 x 815〜935 / 相手 x 990〜1110)。`timer` グリフで 0.8〜0.95。先頭の「+」は縦横がほぼ同じで半分も埋まっていない箱として外す。数字の後ろに何かが付いて 3 桁になる読み違い (28 → 281) があるので 100 を超える値は捨てる。
  - ガチエリア: 相手にエリアを取られた瞬間に、取られた側に付く。値は直前の確保の間に進めた分 (払ったペナルティも含む) のおよそ 3/4 (97 → +74、36 → +28、28 + 14 → +32、12 → +10、37 → +29)。全部のエリアを確保すると、まずペナルティが 1 ずつ減り、その間「のこり」は動かない。誰も確保していない間は残ったまま表示され、0 になると丸枠が消える。
  - ガチアサリ: 攻めが終わったときに付く (23 カウント → +11、54 → +16)。次の攻めではまずペナルティが減る。
  - timeline の `my_penalty` / `enemy_penalty` (`recorder.penalty_series`): 次の読みまで 3 秒以内の空きは直前の値、それより長い空きはそのチームのカウントが読めていれば 0、最後に前後との中央値で 1 回だけの読み違いを消す。
- アサリの「延長中!」の箱は延長の残り時間に合わせて上から黒く抜けていく。延長の判定は文字の部分だけで照合する ([hud.md](hud.md#延長戦))。
- 読んでいないもの: エリアごとの確保状況のアイコン (1 つ / 2 つで位置が違い、背景の色にまぎれやすい)、アサリのチームのアサリの数のバッジ (左右の端、チームの色に白い数字)。

## 表示

Web UI とオーバーレイでは、ナワバリで塗り % を出す所にガチではカウントを出す ([web_ui.md](web_ui.md))。試合詳細の「カウントの推移」のグラフは timeline のカウント / 位置 / ペナルティ / 延長を描く。
