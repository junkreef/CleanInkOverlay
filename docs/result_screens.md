# 試合後の画面 (リザルト表・ジャッジくん・個人パネル)

試合後の 3 つの画面から勝敗・成績を取る。リザルト表が本命で、出ない試合 (スケジュールの切り替わり) はジャッジくん画面と個人パネルで補う ([recorder.md](recorder.md#保存のきっかけ))。

## 数字の読み方 (グリフ集)

数字は OCR ではなく、白文字のマスクの連結成分を 16x24 に正規化し (`result_parser.norm_glyph`)、字形テンプレートとの相関 (Pearson) が一番高い文字にする (`Glyphs.read`)。フォントと位置が固定なので、これで読める。テンプレートは `assets/glyphs/<集>.json` (文字 → 16x24 の平均画像)。

| グリフ集 | 使う所 | 作り方 |
|---|---|---|
| `big` | リザルト表の塗りポイント (大きい数字 + p) | 正解付きのリザルト表 (`result_parser.GT`) から `python work/result_parser.py --build` |
| `small` | リザルト表の x + 2 桁 (たおした / たおされた / SP) | 同上 |
| `pct` | リザルト表の塗り % (太いフォント)、ガチの帯のカウントと行のチームのポイント | 同上 (1 画面に 5 文字しかないので、% だけは正解付きの全画面で作る) |
| `timer` | HUD のタイマー、ガチエリア / アサリの「のこり」と「+N」 | `python work/hud.py --build-timer` ([hud.md](hud.md#タイマー)) |
| `points` | HUD の塗りポイント | クラスタリング + 手でラベル ([hud.md](hud.md#塗りポイント-ナワバリ)) |
| `judge` | ジャッジくん画面の % とカウント | 録画のカウントアップの全コマ (`python work/judge.py --glyphs`) |
| `judge_p` | ジャッジくん画面のチームのポイント | 録画のカウントアップの全コマ (`python work/counts.py --build`) |
| `panel_big` / `panel_small` | 個人パネルの塗りポイント / 小さい数字 | リザルト表のある試合のパネル (`python work/panel.py --glyphs`) |

**穴の数** (`result_parser.HOLES`): リザルト表とパネルの集 (`big` / `small` / `panel_big` / `panel_small`) では、文字の中の閉じた穴の数 (8 は 2、0 / 6 / 9 / p は 1、ほかは 0) を数え、穴の数が合う文字の中だけで比べる。平均のテンプレートだけでは小さい 08 を 06 / 00 と読み、06 を 08 と読むことがあった (8 と 9 は見本が少なかった)。正解付きの全グリフ (大 357 個、小 720 個) で穴の数は例外なく分かれる。テンプレートは作り直していない。

## リザルト表

`work/result_parser.py` (`parse`)。8 行の y (`weapon_match.RESULT_ROWS`、ブキアイコンの上端): WIN! の行 390 / 455 / 520 / 585、LOSE... の行 745 / 810 / 875 / 940。

| 欄 | 範囲 (行の y からの dy、x) | 読み方 |
|---|---|---|
| 塗りポイント | dy 8〜48、x 1320〜1445 | 白 (> 170) の成分 (高さ 22〜45、重なりは結合) を `big` で読み、末尾の p を落とす |
| たおした / たおされた / SP | dy 30〜48、x 1455〜1660 (3 組: x 1465〜1525 / 1530〜1590 / 1595〜1655) | 成分 (高さ 9〜19) を `small` で読み、x で 3 組に分けて先頭の x を落とす。たおした = キル + アシスト |
| 自分の行 | dy 0〜45、x 925〜985 | 黄色い矢印 (R, G > 180、B < 100) が 5% 超 |
| ブキ | dy −15〜55、x 1040〜1130 | [weapon_icons.md](weapon_icons.md) |
| 名前 | dy 5〜45、x 1110〜1320 | 読まない。署名だけ取り、キルフィードの相手の照合に使う ([hud.md](hud.md#自分のキル-キルフィード)) |
| 塗り % | y 235〜285、左 x 925〜1120、右 x 1520〜1710 | `pct` で読む。**左 = 自チーム、右 = 敵** (勝ち負けによらない) |
| バナー (モード / ルール / ステージ) | 右上 | 署名で判定 ([signatures.md](signatures.md#バナー)) |

- 自分の勝敗 = 自分の行が WIN! 側 (上の 4 行) か。
- ガチでは % の所にカウントか「ノックアウト!」、WIN! / LOSE... の行にチームのポイントが出る ([ranked_rules.md](ranked_rules.md#カウントとチームのポイント))。ルールがナワバリでない試合は % を入れない。
- 妥当性チェック (`recorder.result_sane`) は [recorder.md](recorder.md#保存の中身-finish)。
- 精度: 正解付きの 10 画面 (学習 4、ほかはテスト。ガチホコ / ガチヤグラの 3 画面を含む) で全行正しい (`tests/test_result_parser.py`)。保存済みのリザルト表 266 枚を穴の数で読み直したとき、変わった 101 行は全部本物の 08 だった。
- ライブ取り込み (OBS 仮想カメラ) でリザルト表だけを見て解析する単体のツールが `work/live_result_watch.py` (検出したら 1 回だけ解析して PNG + JSON を保存)。

## ジャッジくん画面

`work/judge.py`。Finish! のあと、下のバーに両チームの塗り % がカウントアップし (約 3 秒、ラベルなし)、最終値の約 0.75 秒後に左上に WIN! / LOSE... (黒いしぶきに白文字) が出て、バーと一緒に約 2 秒残る (ラベルはチームのポーズの間も残る)。リザルト表が出ない試合では、勝敗と % が分かるのはここだけ。

- **ラベル** (`read_label`): 左上 (y 40〜150、x 20〜340) の白マスクを WIN! / LOSE... のテンプレート (`work/templates/judge_win.png` / `judge_lose.png`) と照合し、0.7 以上。WIN! は y 61〜118、LOSE... は y 70〜128。保存済みの画面 252 枚 (ルール / 表彰 / リザルト / 試合中) でジャッジくん系以外の最高は 0.32。
- **%**: バーは自分のチームが左 (リザルト表と同じ)。白い数字 68 px (y 862〜931)、左は x 166 から、右は x 1757 まで。リザルト表の `pct` でも読めるが一致度 0.7 前後なので専用の `judge` を作った (録画のカウントアップの全コマを `pct` で読み、「NN.N%」の形で 2 コマ以上同じ読みのものをラベルに。0〜9 そろう)。一致度はきれいなコマで 0.88〜0.98、各文字 0.7 以上を要求。両側が「NN.N%」で合計 100 以下のときだけ採る。
- **隠れた数字**: 飛んでくるイカやステッカーが数字に重なる。右の「38.3%」の 3 が丸ごと隠れて「8.3%」(一致度 0.9) と読めた例があるので、字の箱の外に白い画素が 150 以上ある側は読まない (`OUTSIDE_MAX`。きれいなコマは 99% が 178 以下で中央値 0、隠れたコマは 1000 以上)。
- **投票**: ジャッジくん画面の毎コマが、ラベル (スコア 0.9 以上) と、両側がきれいに読めたときの % で投票し、保存時に多数決 (% は 2 コマ以上一致したものだけ)。録画 1 試合: ラベル 126/126 票、% 25/25 票でリザルト表と一致。
- ガチでは % の代わりに「N カウント」/「ノックアウト!」とチームのポイント ([ranked_rules.md](ranked_rules.md#カウントとチームのポイント))。

## 個人パネル (表彰)

チームのポーズのあとに出る、左に自分のキャラ、右にリザルト表と同じバナー・自分の行・「ゲットした表彰」・ギア 4 枚 (ブキが先頭) の画面。レコーダーは「表彰 (medals)」として検出する (`medals.looks_like_medals`)。**リザルト表が飛ばされる試合でも出る**。

### 自分の行 (`work/panel.py`)

- **バナー** はリザルト表と同じ位置で、`result_parser.banner_identify` がそのまま使える。保存済みのパネル 201 枚で 3 つとも全件リザルト表と一致。
- **塗りポイント**: 白、33〜34 px、y 271〜305 (リザルト表は 27〜28 px)。**x03 ×3**: 数字 20 px、y 295〜315、x 1515 / 1593 / 1670 から。リザルト表の集で読むと小さい 6 を 8 と読むことがあったので、専用の `panel_big` / `panel_small` を作った (リザルト表の自分の行が正解)。半分で作って残り 100 試合で試すと 100/100、一致度の最低 0.71、2 位との差の最低 0.12。行の最低一致度が 0.6 (`GLYPH_MIN`) 未満なら数字は全部捨てる。パネルでまだ見本の無い数字はリザルト表の `small` から借りる (`python work/panel.py --glyphs` で作り直す。2026-11-04 の作り直しで小さい 9 にも見本ができ、今は全部の数字がパネル自身の見本。見本の数が一番少ないのは小さい 9 の 2 枚、7 の 17 枚、8 の 13 枚。作り直したあともパネル 378 枚が全部リザルト表と一致)。
- **ブキ**: ブキカードのアイコンは毎回まったく同じ絵 (グレー 32x32 の相関 0.9999 以上、別のブキで 0.57) だが、ブキアイコンのテンプレートとの照合では全パネルで別のブキを選んだ。なので**覚える**: アイコン (y 805〜915、x 885〜990) の 24x24 カラー縮小を署名 (kind `panel_weapon`) にし、リザルト表もある試合でリザルト表の自分のブキ (一致度 0.94 以上) のラベルを付ける。リザルト表の無い試合では照合だけ (しきい値 0.97、新しい署名は作らない)。
- リザルト表が無い試合では、パネルの自分の行・ステージ・モード・ルールを入れる。自分のスロットは HUD 3:00 のアイコンとパネルのブキの照合 (味方 4 枠、デス回数でタイブレーク)。スロットが分かると、キル (相手は不明) とやられた相手 (吹き出しのカード → スロット) のイベントも入る。
- ブキを覚えていない (そのブキで一度もリザルト表まで見ていない) か、試合開始 (3:00 の HUD) を見ていないと、自分の行は入らない (勝敗と % だけ)。ナワバリ以外の試合で開始のアイコンが無いときはスロット 0 にする (`link_score` NULL = 並びは任意)。味方・敵の行はパネルに無いので入らない。

### 表彰 (`work/medals.py`)

- 黒いパネルに「ゲットした表彰」の見出し (白文字、y 384〜413、x 868〜1016) と斜めのバナー最大 3 枚。検出は見出しの白マスク (> 200) がテンプレート (`medals_header.png`) と相関 0.8 超、かつパネルの暗部 0.3 以上。リザルト表・ロビーは 0.0。
- バナーは枚数が少ないほど大きく描かれるので、枚数ごとに固定のレイアウトがある (`LAYOUTS`: 3 枚の画面 87 枚は画素単位で同じ、2 枚・1 枚は各 1 画面で測定)。枚数はパネル内の白い箱の数で決める。
- 3 枚のときのバナー i (0〜2) の白い箱の左上は (962, 444) / (1140, 513) / (1318, 582)、大きさ 378x92。左のイカのアイコンが黄色 (15% 超) なら金、灰色なら銀。
- 本文 (白地に暗い字、最大チャンネル < 90) を 3 枚のときの大きさ (315x65) にそろえてから署名にする (kind `medal`、[signatures.md](signatures.md#表彰))。
- DB には `medals` (match_id, name, rank, position, sig_id) と `matches.medal_image`。
