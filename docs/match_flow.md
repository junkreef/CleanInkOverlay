# 1 試合の画面の流れ

ゲームが試合ごとに出す画面と、それぞれから何を取るか。レコーダーがこれをどう追うかは [recorder.md](recorder.md)。

## ナワバリバトル

録画 `2026-09-12_14-13-43.mp4` の 1 試合目 (動画内の秒) と、`2026-10-11_22-14-08.mp4` (試合後の画面) で測った流れ。

| 秒 | 画面 | 使い道 |
|---|---|---|
| 0〜36 | ロビー (マッチメイク中) | 何もしない |
| 38 | 暗転 → ルール画面 (「ルール / ナワバリバトル」、8 人のプレイヤーカード) | ルール名 (解析の切り替え)、カード (やられた相手の照合用)。左列 = 自チーム、右列 = 敵。**カードの並び = 試合中の HUD のイカ枠の並び**。表示は 2.0〜6.5 秒 |
| 46〜52 | 登場演出 (HUD なし) | 無視 |
| 52.3 | HUD 出現、タイマー 3:00、Ready? | 3:00 のうちにイカ枠のブキアイコンを保存 (全員生存中) |
| 55 | GO! | |

| 176 | 「あと 1 分!」、タイマーが黄緑に変わる | タイマーは白ではなく「明るい」で読む ([hud.md](hud.md#タイマー)) |
| 235 | Finish!、HUD 消失 | 試合の終わり |

| 〜 | チームのポーズ (ラベルは残る) → 暗転 | |

| 〜 | ロビー | |

`2026-10-11_22-14-08.mp4` の例: Finish! 256〜260 秒 → カウントアップ 262〜265 → 265.0 で最終値 → 265.75 から WIN! / LOSE... → % バーは 268.0 まで → ポーズ (〜278) → 暗転 → 個人パネル 282 → リザルト表 292 → ロビー。

- 試合は 3:00。3:00 の表示は HUD 出現から約 4 秒続く。
- 負け試合のリザルト表は WIN! (敵) が上、LOSE... (自分) が下。自分の行には黄色い矢印が付く。
- 塗り % のバーは勝敗によらず「左 = 自チーム、右 = 敵」(ジャッジくん画面もリザルト表も)。
- マップ (X ボタン) を開くと HUD は全部消える ([hud.md](hud.md#マップ))。

## ガチルール (バンカラマッチ)

録画 `2026-10-28_22-51-57.mp4` (ガチホコ 2 試合) と `2026-10-28_23-06-42.mp4` (ガチヤグラ 4 試合) で確認。ガチエリア・ガチアサリも同じ流れ。

1. ルール画面 (「ルール / ガチホコバトル / ガチホコを相手ゴールに運べ!」)。レイアウトはナワバリと同じ。
2. HUD はタイマー **5:00** から。タイマー・イカ枠・キルフィード・吹き出しの位置はナワバリと同じだが、右上の塗りポイントが無い。
3. ノックアウト (カウント 100) か 0:00 で終わる。0:00 のあと延長戦 (タイマー欄に「延長中!」、最長 5 分) になることがある (ガチホコ 2 試合目はリードしていて延長なしで終了、ガチヤグラ 4 試合目は約 9 秒の延長)。
4. ジャッジくん画面は塗り % ではなく「N カウント / Np」のカウントアップ → 「ノックアウト!」500p / 「0カウント」0p など。WIN! / LOSE... はナワバリと同じ。
5. 個人パネル (バナーに「バンカラマッチ(チャレンジ) / ガチホコバトル」) → おカネ / ランク / ギア → リザルト表。
6. リザルト表の上の帯は % バーではなく両チームのカウント (またはノックアウト!)、WIN! / LOSE... の行の右端にチームの「500 p」。

詳しくは [ranked_rules.md](ranked_rules.md)。

## スケジュールの切り替わり

スケジュールが変わる時刻 (例: 23:00) をまたいだ試合では**リザルト表が出ない**。個人パネル → おカネ / ランク のあと、普通ならリザルト表が出るところで、中央の黒いしぶきに白い字で「スケジュールが更新されました」が約 0.9 秒出て (y 528〜575、x 776〜1143)、暗転・セーブ → ロビーに戻る (`2026-10-28_22-51-57.mp4` の 2 試合目、744.3〜745.2 秒)。

ジャッジくん画面と個人パネルは出るので、勝敗・% (またはカウント)・自分の行・ステージ・表彰はそこから取る。この通知を見たらレコーダーはその場で試合を保存する ([recorder.md](recorder.md#保存のきっかけ))。ナワバリの切り替わりで同じ通知が出るかは録画で確かめていない。

## イベントマッチ

録画 `2026-10-11_22-14-08.mp4` (ツキイチ・イベントマッチ、ルールはナワバリ)。

- ルール画面の「ルール / ナワバリバトル」の下にピンクのイベント名タグ (「ツキイチ・イベントマッチ」、y 640〜730) が入り、黒い説明タグが 70 px 下 (y 735〜812) にずれる。ルール画面の判定は説明タグを y 685 と y 755 の両方で見る ([recorder.md](recorder.md#画面の判定))。
- HUD・カード・個人パネル・リザルト表のレイアウトは通常と同じ。
- リザルト表のバナーの上段のタグが「イベントマッチ」と「ツキイチ・イベントマッチ」の 2 つになる。1 つ目は既存のモードの位置で読める (モード「イベントマッチ」)。2 つ目 (イベント名) は読んでいない。
- イベントマッチはナワバリ以外のルールのこともある。ルール名に名前の無いルールは、開始時のタイマーの値を試合の長さとして記録する ([ranked_rules.md](ranked_rules.md#解析の選び方))。

## フェスマッチ

2026-10-31 のフェス (オープン) はナワバリとして記録できる。リザルトのバナーのモードは「フェスマッチ(オープン)」、ルール画面のルール名はナワバリと同じ署名。

- ルール画面のカードの上に「ふつうのナイト派」(ランク + 陣営) が入り、カードの間隔が 150 px → 200 px になる。カードの上端は y 285 / 435 / 585 / 735 ではなく **195 / 395 / 595 / 795** (x は同じ)。
- 見分け方 (`rule_screen.card_tops`): カードの上の文字 (白 + 黒ふち)。左右の帯 (y 158〜194) の中の「黒に接する白」の割合がフェス 0.13〜0.19、それ以外の 310 画面は 0.03 以下なので、両側 0.06 以上 (`FEST_TEAM_MIN`) でフェスとする。ルール画面の判定 (`looks_like_rule`) とカードの切り出し (`read_cards`) の両方がこの位置を使う。
- 通常の位置で切ると 3 段目しか合わず、吹き出しとの照合が 0.41 / 0.40 で相手不明になっていた。正しい位置なら 0.93 / 0.89。
- トリカラマッチ (4 対 2 対 2) は未対応。

## 試合の途中から / 中断

- **レコーダーを試合の途中で起動した**: ルール画面も HUD の開始も見ていないので、リザルト表が来たらそれだけで保存する (`notes = 'no rule screen'`、時系列なし)。
- **通信エラーで中断 → 再開**: ルール画面なしで新しい試合が 3:00 (ガチは 5:00) から始まることがある。試合中にタイマーが開始値に戻ったら (開始から 30 秒以上たっていれば) 前の試合を捨てて始め直す (`notes = 'restarted without rule screen'`、カードは不明)。
- **試合中にルール画面**: 前の試合は中断とみなして捨て、新しい試合を始める。
