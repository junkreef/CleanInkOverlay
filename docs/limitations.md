# 既知の制限・未確認・未対応

## 前提

- 入力は **1920x1080** の映像。座標は全部 1080p の固定値で、ほかの解像度に合わせる処理は無い。
- ゲームの表示言語は **日本語**。署名・テンプレートは日本語 UI の文字の見た目で作ってある。
- ライブ取り込みは Windows の DirectShow (OpenCV `CAP_DSHOW`、デバイス列挙は pygrabber)。
- 入力の 60 fps のうち 6 コマに 1 コマだけを解析する。コマを増やしても良くならないことは確かめてある ([recorder.md](recorder.md#コマを増やしても良くならない-2026-10-30-の調査))。

## 記録の精度

- **他の人のスペシャル** は取っていない (回数はリザルト表から)。スロットのアイコンがスペシャルのアイコンに置き換わる (自分のスロットで確認) ので、アイコンとの照合で取れるかもしれない。チームの色に依存する特徴量は使えない。
- **他の人のデス数** は位相で ±1〜2 揺れる (ガチエリアで 55〜59)。背景が暗い場面で、灰色っぽいアイコン (ホクサイなど) の枠がやられていないのに暗さ 0.24〜0.30 になり、しきい値 0.25 の境目にいる。
- **自分のデス** がリザルト表と一致するのは、録画 9 試合 × 6 位相で 54 件中 47 件 (ヤグラ 3・4 試合目が位相で 8〜9、リザルト表は 8)。
- **やられた吹き出しの取りこぼし**: 吹き出しが短くしか映らないとき (試合終了 0.1 秒前のデス、吹き出しの表示中にマップを開いた) は位相によって拾えない。Finish 直前のデスや、デス直後にマップを開いたまま復活したときは吹き出し自体が出ない。吹き出しの無い自分のデスは `samples/misses/` に前後のコマを残すので、ライブで出たら原因を見る。
- 吹き出しの照合の証拠は今は全部保存している (`BUB_EVIDENCE_BELOW = 1.01`)。ライブの正例が溜まったら 0.8 に下げる予定。ライブでは照合点が 0.25〜0.49 で相手不明になった例がある (カードの取り直しより前、切り出しを保存していなかったので原因は不明)。取り直しのあとのライブ (2026-10-31 のフェスマッチ 1 試合) では吹き出し 3 件の相手がゲーム内の表示と全部一致した (0.85〜0.92)。
- **キルフィード**: 完全に同時の 2 キル (2 段が同時に出る) はまだ撮れていない。アシストは通知が無いので、キルの件数はリザルト表の「たおした (キル + アシスト)」より少ない。
- **同じチームに同じブキが 2 人以上** いると、その 2 人のスロットと行はアイコンでは決まらない (デス回数の差、それも同じなら実質ランダム、[weapon_icons.md](weapon_icons.md#hud-スロットとリザルト行の紐づけ))。
- HUD の最後の塗りポイントはリザルト表より少ないことがある (HUD が消えたあとの塗り)。

## ブキアイコン

- 配布するのは自前のテンプレートだけ (2026-11-10 時点でメイン 174 種の全部にある)。テンプレートに合わないアイコンは、ライブで見るたびに未知のグループになり、Web UI で名前を付けるまで `weapon` が空になる。wiki アイコンが手元に無いと推定 (確認待ち) も出ない。
- サンプル集めと未知のグループはライブだけ。録画 (H.264) の画面からは作らない。
- 4K のスコープは暗すぎて `variant` の判定 (形の許容 4) に引っかからない。両方のテンプレートがあるので照合では問題にならない。

## 試合の保存

- **ライブのループを止めたとき、途中の試合は保存しない**。リザルト表の出ない試合は、スケジュール更新の通知・次のルール画面・ジャッジくん画面か表彰が消えて 60 秒 (見ていなければ HUD が消えて 300 秒) のどれかで保存されるので、その前に止めると消える。
- **すぐ飛ばされたリザルト表**: 落ち着いた画面が 2 サンプル (0.1 秒あけて) 続かないと読まない (滑っている途中のコマは読み違えるため)。落ち着いて 0.2 秒未満しか出なかったリザルト表は位相しだいで取れない。0.1〜1 秒で飛ばした録画は無く、短いリザルト表はテスト (ずらしたコマで作った出入り) でしか確かめていない ([recorder.md](recorder.md#表彰とリザルト表が短いとき))。
- 時間切れ (60 秒 / 300 秒) で保存したあとにリザルト表が来ても、その試合には足さない (ログに出すだけ)。60 秒はライブのナワバリ 291 試合の最長 (表彰から約 29 秒) の 2 倍で、ガチでおカネ / ウデマエの画面が長引いた例は測れていない。
- **再起動での重複**: リザルト表が出ている間にバックエンドを再起動すると、同じ試合が「リザルトだけ」でもう一度保存される。二重保存を防ぐ `t_last_store` がメモリ上にしかないため。仕組みの修正は見送り中 (重複は手で消す)。
- 「スケジュールが更新されました」はガチホコの録画で 1 回だけ確かめた。ナワバリの切り替わりで同じ通知が出るかは未確認。見逃したときはこれまでどおり次のルール画面か 300 秒で保存する。
- 個人パネルだけの試合で自分の行が入るのは、そのブキのパネルのアイコンを覚えていて (一度リザルト表まで見ている)、試合開始の HUD を見たときだけ。
- 個人パネルの小さい数字の 9 は見本が 2 枚しかない (7 は 17 枚、8 は 13 枚)。試合が増えたら `python work/panel.py --glyphs` で作り直す。
- **メモリープレイヤーの再生** は左上のマークで見分けて記録しない ([recorder.md](recorder.md#メモリープレイヤーの再生))。確かめたのは 2026-04 の録画 1 本 (ナワバリ、止めずに最後まで再生) だけ。一時停止・早送り・カメラの切り替え・メニュー・操作説明の「非表示」でマークが消えるかは未確認で、消えるならその間は試合として読んでしまう。再生の最後のマークの無い画面が 30 秒 (`REPLAY_HOLD`) より長く続いたり、そのあとにリザルト表や表彰が出たりする場合も未確認。
- ルール画面を見ずに途中から通した試合は、リザルト表のバナーのルールに名前が無いとナワバリ扱いになる (% が入る)。

## 未対応のルール・画面

- **トリカラマッチ** (4 対 2 対 2)。
- **フェスマッチ**: ルール画面のカード配置は対応済みだが、フェスの録画がまだ無いので、フェスのカードのフェードイン中のコマと 6 位相は未確認。
- **イベントマッチ**: イベント名 (リザルト表の 2 つ目のタグ) とイベントパワー (試合後の「現在のイベントパワー / イベントパワー最高値」と変動値) は記録しない。記録するなら署名の種類と `matches` の列 (Alembic の移行)、イベントパワー用の数字のグリフ集が要る。
- **ガチエリア**: エリアごとの確保状況のアイコンは読まない。リザルト画面は 1 試合分 (2026-11-04) だけで、ステージ名は stage_x から半ピクセル右 (0.94) で読めている。
- **ガチアサリ**: チームのアサリの数のバッジ (左右の端) は読まない。
- **ガチのリザルト表の帯** で読めたことのある数字は 0, 2, 3, 4, 5, 6, 9。1・7・8 は未確認 (ジャッジくん画面の読みと突き合わせてログに出る)。
- **リザルトのバナーのルール名** は、名前が付いているのがナワバリバトル・ガチヤグラ・ガチアサリ・ガチエリアで、ガチホコバトルは次に見たときに Web UI で名前を付ける (名前が付くまでは、試合のルールにルール画面の名前が入る。解析の切り替えもルール画面の名前で決まる)。

## ライブ取り込み

- ライブのループの `grab()` / `retrieve()` (解析するコマだけ取り出す) が仮想カメラで `read()` と同じに動くかは未確認 (OpenCV の DirectShow では `read` = `grab` + `retrieve`)。
- 「OBS Virtual Camera」は OBS が仮想カメラを止めていてもデバイスとして見えるので、開けても映像が来ないことがある。
- **色を変えるフィルター (OBS の色補正・LUT など) のかかった映像は読めない**。判定はゲームの元の色が前提で、補正後の映像ではリザルト表のブキアイコンが見本と合わず、リザルト表を捨てる (ログの `result screen did not parse sanely`、その試合は勝敗と % だけになる)。明るさ・コントラストが変わるとルール画面も認識できなくなる。フィルターはソースに付くので、仮想カメラの出力タイプを「ソース」にしていても補正後の映像が来る。説明書で、フィルターを外すかシーンに付け替える方法を案内している ([#7](https://github.com/junkreef/CleanInkOverlay/issues/7))。色の違いに気づいて知らせる処理は無い。

## 配布パッケージ

- **ルール画面の判定は映像の明るさの段階に弱い** (2026-11-13 の調べ)。「ルール」タグの黒は実測で最大チャンネル 22 なのに判定は 40 未満、白文字は 200 超、カードの `#nnnn` のコントラストは 100 以上 (保存済みのルール画面 539 枚の 9% のカードが 100 未満、102 ちょうどが多い。539 枚中 92 枚は 8 枚中ちょうど 6 枚で通っている)。保存済みの画面に段階の変化を加えると、黒が +20 浮くだけで 534 枚中 0 枚、フルレンジ → リミテッド (16〜235) で 407 枚、白が 200 まで沈むか、HDR → SDR のトーンマップに似た変化 (黒 25・白 220) で 0 枚になるのに、ジャッジくん画面・表彰・リザルト表・ステージ名は同じ変化で読める。逆に 720p の拡大、数 px のずれ、少しの拡大縮小ではルール画面はほとんど落ちない (落ちるのはステージ名やリザルト表の行)。ルール画面を見逃して試合が始まったら `RULE SCREEN MISSED?` のログと証拠のコマが残る ([recorder.md](recorder.md#証拠の画像))。
- **Xマッチのルール画面** はまだ一度も認識できていない (2026-11-12 の 2 試合とも、DB 703 / 704)。同じ夜のバンカラマッチは認識した。Xマッチのルール画面に何が足されるかは未確認。
- ルール画面を見逃した試合は、リザルト表だけで保存される (時系列・やられた相手なし)。HUD の開始 (タイマー 3:00 / 5:00) から試合を始めることはできるが、入れていない (カードが無いのでやられた相手は分からなくなる)。
- **作者の環境 (キャプチャーボード 1 機種 + OBS の仮想カメラ) でしか確かめていない**。ほかのキャプチャー機器や OBS の設定 (色の範囲、拡大縮小のフィルター) で画素が変わると、「ライブの取り込みは無劣化」を前提にした判定 (ブキアイコンのサンプル集め、署名の一致) が同じように働くかは分からない。
- コード署名が無いので、初回の起動で SmartScreen の警告が出る。更新の通知も無い ([release.md](release.md#分かっている弱いところ))。
- 開発用のスクリプト (`work/*.py` の `main`、テスト) は `cv2.imread` を使うので、日本語などを含むパスに置いた作業ツリーでは動かない。実行時のコードは対応済み。

## 案 (未着手)

- 表彰のバナーの本文も文字のグリフで読めれば、新しい表彰が自動で名前付きになる (今は署名 + 手でラベル)。
- **署名とブキのテンプレートの管理画面**: 今の Web UI でできるのは、未知のものに名前を付けることだけ。付けた名前の修正・取り消し、一覧、書き出し (ほかの人や作者に渡す) と取り込み、配布版との突き合わせは無い。今は、名前を付け間違えたらデータフォルダーのファイルを手で直し、共有は `assets` フォルダーを zip にして Issue に付ける ([release.md](release.md#配布したライブラリと使う人が足した分))。
- `looks_like_result` に WIN! の見出しの確認を足せば、ロビー画面を誤認しないための妥当性チェック (`result_sane`) を軽くできる。
